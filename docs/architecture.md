# Architecture

The React client calls same-origin `/api` endpoints. Vite proxies these to FastAPI during development; FastAPI serves the built frontend for local deployment. SQLAlchemy persists metadata, article embeddings, company/topic relationships, chat sessions, briefings, preferences, video metadata, source status, and ingestion jobs. A schema version table tracks the initial additive migration. One local user is seeded; all personas and companies are seeded from the fixed eight-person roster.

Chats has its own saved-history workspace. Read-only `/api/chat/sessions` supports bounded limit/offset pagination ordered by last message activity; `/api/chat/sessions/{uuid}` restores messages, source context, topic, related-reporting preference, and follow-up fields. Existing sessions need no migration. Source expiry does not delete conversations. React keeps feed filters and reading position separate from the active chat and restores them through Back to articles; an answer may finish without changing the feed view. A 60-second client poll reads cached news and queues changed rows behind Show updates. Polling does not trigger publisher ingestion or a page reload.

Ingestion fetches a fixed registry with bounded concurrency and per-source failure handling. Public HTML adapters check robots.txt, read announcement links and structured metadata, and avoid category directories. Canonical URLs strip tracking and fragments. Missing dates remain null. Deduplication checks canonical URL and normalized headline. Title/excerpt embeddings support conservative classification alongside exact entity boundaries and official source identity. This is not a trained named-entity model; it combines a fixed entity registry with semantic representations.

Chat infers temporal intent, identifies target companies, retrieves candidates, ranks lexical relevance and cosine similarity, and preserves relevant companies in comparisons. It sends at most ten collected source records, six cited live-research sources, and six recent history items to the OpenAI Responses API. Referential follow-ups rehydrate previously cited article IDs from the database before ranking; generated history is conversational context, never evidence. Generic answers constrain citation IDs with a per-request schema and label source-based reporting, analysis, predictions, and general explanations. Missing evidence permits explicitly conditional reasoning, without invented event facts. An invalid output triggers regeneration; repeated citation errors trigger a fresh citation-free general assessment rather than publication of an invalid draft. Article explanations independently review and repair passage citations, permitting clearly labeled inference without source claims. These checks validate source identity, not proof of every generated claim or prediction; readers can inspect original reporting.

`research.py` runs two bounded research searches: original documentation/implementation and independent evidence/limitations. It plans focused queries and accepts source URLs only from tool-issued citation annotations or completed search-result metadata, then filters them to a registry of company, research, official-record, and established-news domains. Filtering is enforced locally because the configured GPT-4.1-mini search tool rejects provider domain filters. It rejects nonpublic links, incomplete results, and model-written URLs without citation metadata. Up to eight vetted search-result URLs are considered for direct reading, with four concurrent requests, robots checks, trusted-domain checks on every redirect, a 1.5 MB response limit, and at most four short source paragraphs retained. Blocked, non-text, oversized or inaccessible pages are skipped. Fetched public source excerpts and AI search syntheses have different provenance labels. A separate grounded review improves generic answers as well as the existing article/video review. Up to six sources and 64 cached research dossiers are retained for 15 minutes in memory. Article/video related-context opt-out bypasses search. Search failure or limited corroboration produces explicit coverage metadata rather than a fabricated research claim. One research dossier is shared across the companies answering a question. General answers have five validated research sections with per-section source IDs; article/video review instructions preserve roughly 450–700 words of useful depth. Larger generation budgets apply only to answer calls, not feed summaries. The UI displays coverage, source count, and reading time and persists the complete explanation and research metadata in existing chat JSON. Long answers open at the beginning of the newest response, and Listen splits the full explanation into existing bounded audio tracks instead of truncating it.

AI summarization is bounded to eight new items per ingestion. Other cards show labeled source excerpts. Recommendations are off until opted in, and combine recency, explicit topics/companies, and saved-article embedding similarity. No accuracy metric is claimed.

Interactive questions are generated within the existing structured answer/review calls, with no separate suggestion-generation request. Shared schemas add `follow_up_question`, `reply_options`, and `suggested_questions`; normalization bounds/deduplicates choices and falls back safely if suggestion metadata is malformed. These fields persist in existing chat JSON, so no schema migration is needed. Suggested replies/questions submit to the existing chat endpoint with `follow_up: true`, the same session, presenter and source scope. Typed replies also continue a pending clarifying question; chat/video model context includes the CEO's question. React keeps only the latest matching conversation group's choices active, accepts custom replies through the composer, and narrates the CEO question with the answer.

APScheduler handles ingestion every 30 minutes, morning/evening briefings at selected local times, and weekly summaries on Sunday. Cron triggers use IANA timezone data for DST. The scheduler requires one active server process. Audio is cached by model, voice, and text hash. YouTube queries are restricted to channel IDs returned for registered official handles.

API data requires an account session. Registration/login/logout mutations use a separate CSRF cookie/token pair; cross-origin writes and unknown hosts are rejected. Passwords use salted scrypt and revocable seven-day sessions store only token hashes. Schema version 4 adds accounts, session ownership, audio grants and billing records. Existing conversations are assigned to the local owner; first registration through localhost claims that history. Preferences and chat queries use request-local account context. Public article/video reporting and briefing snapshots remain shared server content. The verified deployment remains one local backend worker.

Stripe prices are fixed server-side at USD 200/300/500 cents per month. Card/wallet selections create hosted subscription checkout; bank transfer creates a send-invoice subscription; QR links encode only an owned Stripe URL. Persistent pending orders and stable idempotency keys prevent duplicate retries. Only a paid invoice and active subscription with verified customer, account, quantity and price activate membership. HMAC-verified, recent webhooks are replay-safe. Stripe activation awaits local credentials. Account language is appended to answer/review prompts and stored with each resulting chat message; the interface and original reporting are not translated.

Video-scoped chat rechecks the selected ID with YouTube `videos.list`, accepts only a completed public upload owned by a pinned official company channel, and passes its canonical YouTube URL to Gemini's multimodal Interactions API. Structured observations preserve uncertainty and approximate timestamps, converted from MM:SS/HH:MM:SS to seconds and checked against the API duration. Failed, malformed, truncated, or out-of-range analyses are withheld. A bounded 24-hour in-memory cache coalesces identical requests; context changes get fresh analysis. No media is downloaded and authenticated caption access is not assumed.

Video observations and official metadata have separate source kinds. Question embeddings retrieve relevant observation passages before optional related article excerpts. The verified owner, relevant companies in the video, and companies explicitly asked about get separate OpenAI explanations and independent grounding reviews. Validated IDs map to the selected official video and timestamp links. A supported answer must cite actual video observations. Returned observations remain AI interpretations, not verified transcripts or independent proof of company claims. The browser persists the selected video and displays its CEO avatar during analysis; completed explanations can use the existing generic TTS service.

OpenAI API contracts were checked against [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) and [text to speech](https://developers.openai.com/api/docs/guides/text-to-speech).


Profile/password endpoints require an account and CSRF token. Password replacement verifies the existing hash, rejects reuse, revokes all previous sessions and rotates the current cookie. Billing history filters local attempts by account and Stripe invoices by its customer ID, validates returned ownership, removes unsupported external links and bounds invoice pages. Renewal mutations verify the subscription customer/account and update only cancel_at_period_end. These operations never delete a subscription or issue a refund.


Schema version 5 adds session last-seen timestamps and preserves only unassigned legacy audio for the owner. The security envelope enforces browser policies, body/time limits and bounded request buckets before API parsing. CSRF is signed, expiring and bound to the current login cookie. Authentication also bounds identity/IP attempts and active sessions. Audio reads always require an explicit account grant. Source fetches recheck their outbound allowlist on each redirect. See SECURITY.md for deployment boundaries and advisory audit scope.
